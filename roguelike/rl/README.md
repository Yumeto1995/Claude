# 強化学習（敵AI）

ゴブリンの行動を**表形式Q学習**で学習する。依存は numpy のみ（PyTorch等は不使用）。

## 使い方

```bash
# 学習（roguelike ディレクトリで。10万エピソードでも10秒程度）
python3 -m rl.train --episodes 100000

# 保存済み方策の評価だけ
python3 -m rl.train --eval-only
```

学習すると `rl/policy.npz` が保存され、**次のゲーム起動からゴブリンが学習済み方策で動く**。
ファイルを消せば従来のA*追跡に戻る（コード変更不要）。スライムは比較用にA*のまま。

## 全体の構造

```
ゲーム本編                          学習側（このフォルダ）
─────────────                      ─────────────────────
components/ai.py                   rl/train.py   学習ループ
  RLEnemy.perform()  ←─ policy.npz ─  rl/qlearning.py  Q学習（numpy）
    │                                  rl/env.py     アリーナ環境（reset/step）
    └── rl/obs.py（観測エンコード。学習と本番で同じ関数を共有）
```

- **rl/env.py**：9×9の小部屋で「ゴブリン vs プレイヤーbot」を1対1で戦わせる
  gym風環境。ダメージ計算・移動判定は本編の `actions.py` / `combat.py` を
  そのまま呼ぶので、学習した方策は本番ダンジョンでも同じ力学で動く。
  エピソードごとに 1〜6階相当の強さのゴブリンを抽選（本編の階層スケールと同じ式）。
- **プレイヤーbot**：隣接していてスタミナがあれば攻撃、なければ待機して回復、
  離れていれば接近（まれにランダム）。本編プレイヤーの単純化。

## 状態・行動・報酬の設計（rl/obs.py, rl/env.py）

| 要素 | 内容 | サイズ |
|------|------|--------|
| 相対位置 | プレイヤーとの dx, dy（±4に丸め） | 9×9 |
| 自分のHP | 比率を高/中/低の3段階 | 3 |
| 相手のHP | 同上 | 3 |
| 相手の臨戦 | プレイヤーが今攻撃できるか（スタミナ） | 2 |

状態数 1458 × 行動 9（8方向＋待機）。HPを**比率**で持つので、
階層スケールで強化された個体でも同じQ表が使える。

報酬：与ダメ +2/点、被ダメ −1/点、撃破 +30、死亡 −15、
1ターン −0.02、生き残り +5（値は `env.py` の `R_*`）。

## 学習で獲得された行動の例

- 自分のHPが低く、プレイヤーが攻撃可能 → **逃げる**
- プレイヤーのスタミナが切れている → **接近して殴る**
- 非隣接でプレイヤーが臨戦状態 → **待機**（無闇に近づかない）

つまり「スタミナ切れを狙うヒット＆アウェイ」の素地が出ている。
報酬の係数を変えると性格が変わる（攻撃的⇄臆病）ので、調整して再学習→
`--eval-only` やゲーム内で比較すると面白い。

## 本番側の動き（components/ai.py の RLEnemy）

- 起動後の初回だけ `policy.npz` を読み込み、**全個体でQ表を共有**
  （クラス属性なのでセーブデータには入らない＝セーブが太らない）
- プレイヤーが視界内かつ±4マス以内 → Q値の高い行動から順に、
  実行可能なもの（壁・他の敵・セーフルームを避ける）を選ぶ
- 遠距離・方策ファイルなし → 従来の `HostileEnemy`（A*追跡）にフォールバック
- 同士討ちの気まぐれ（25%）は従来通り

## 次のステップ候補

- 報酬・対戦相手（bot）の改良：装備持ちbot、回復薬を使うbot
- 観測の拡張（壁の有無、他の敵）→ 状態数が増えたら関数近似
  （numpy で線形近似 or 小さなNN）へ移行
- スライムなど他の敵種の学習（種族ごとに別ファイル）
- 自己対戦・カリキュラム学習
